Mayfly · live demo

Watch a CI job run in a MicroVM that's already gone.

Click the button. A fresh, single-use AWS Lambda MicroVM boots in your CI, runs one job, reports the MicroVM id AWS assigned it at launch, and is destroyed — its own isolated kernel, nothing shared, nothing left behind. Trigger twice: a different MicroVM id each time is what a fresh VM looks like.

…

Each run is a brand-new Firecracker MicroVM on Graviton (arm64). It exists for one job, then it's gone.

GitHub workflow_job→ Function URL→ SQS→ control Lambda→ run-microvm→ JIT runner→ terminate

The control plane provisions one MicroVM per queued job (auto-suspend off so it survives the job), hands it a single-use JIT runner over the L7 endpoint, and reaps it on completion. A scheduled reconciler reclaims anything a teardown ever misses. This page just shows the receipts each VM leaves behind.
